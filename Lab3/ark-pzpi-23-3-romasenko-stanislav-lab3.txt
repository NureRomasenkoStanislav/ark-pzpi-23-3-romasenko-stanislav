3 ОПИС ВИКОНАНОЇ РОБОТИ
1. Текстовий опис інженерних рішень
У межах даної роботи було реалізовано перехід від простої CRUD-моделі (ЛБ 2) до повноцінної трьохрівневої архітектури з використанням патернів Service Layer та Dependency Inversion.
1.1. Проектування бізнес-логіки
Центральним елементом системи став сервіс BookingService, який інкапсулює правила перевірки можливості бронювання. Головним інженерним рішенням є впровадження алгоритму детекції часових колізій (Time Collision Detection). На відміну від простого запису в БД, сервіс проводить аналіз існуючих інтервалів у межах конкретної кімнати.
Математична модель перевірки конфлікту:
Для нового бронювання з інтервалом [Snew,Enew] та будь-якого існуючого запису  [Sext,Eext], конфлікт виникає за умови:
(Snew<Eext)(Enew>Sext)
Ця формула гарантує, що жодне бронювання не буде накладене на інше, навіть частково.
1.2. Функції адміністрування та моніторингу
Для забезпечення стабільності та керованості системи реалізовано:
System Maintenance Mode: Глобальний параметр стану системи, що реалізований через ISystemStateService. Він дозволяє адміністратору миттєво обмежити доступ до критичних операцій
Audit Logging: Система автоматичного моніторингу, що фіксує всі адміністративні дії (зміна ролей, видалення об'єктів) у таблиці AuditLogs.
Role-Based Access Control (RBAC): Розмежування прав доступу на рівні контролерів за допомогою атрибутів авторизації.
2. Графічні ілюстрації UML
2.1. Діаграма діяльності (Activity Diagram)
Візуалізує логіку обробки запиту на бронювання, включаючи перевірку стану системи, валідацію часу та перевірку конфліктів.
2.2. Діаграма взаємодії (Sequence Diagram)

3. Фрагменти програмного коду
3.1. Реалізація бізнес-логіки (BookingService.cs)
Код демонструє використання ін'єкції залежностей та алгоритму перевірки колізій.
public async Task<bool> ProcessBookingAsync(Booking booking)
{
    if (_systemState.IsMaintenanceMode)
        throw new Exception("Система на технічному обслуговуванні.");
    if (booking.StartTime < DateTime.UtcNow || booking.EndTime <= booking.StartTime)
        throw new Exception("Некоректний часовий інтервал.");
    var existingBookings = await _repository.GetByRoomIdAsync(booking.RoomId);
    foreach (var existing in existingBookings)
    {
        if (booking.StartTime < existing.EndTime && booking.EndTime > existing.StartTime)
            throw new Exception("Кімната вже зайнята на цей час.");
    }
    var success = await _repository.AddBookingAsync(booking);
    if (success)
    {
        await _adminRepository.LogActionAsync(booking.UserId, "CREATE_BOOKING", $"Room ID: {booking.RoomId}");
        await _iotService.UnlockRoomAsync(booking.RoomId);     }
    return success;
}
3.2. Функції адміністрування (AdminController.cs)
Код для управління ролями, логами та системними параметрами.
[Authorize(Roles = "Admin")]
[Route("api/[controller]")]
public class AdminController : ControllerBase
{
    [HttpPost("maintenance")]
    public IActionResult ToggleMaintenance([FromBody] bool enabled)
    {
        _systemState.IsMaintenanceMode = enabled;
        return Ok(new { Status = enabled ? "Enabled" : "Disabled" });
    }
    [HttpGet("audit-logs")]
    public async Task<IActionResult> GetLogs() => 
        Ok(await _context.AuditLogs.OrderByDescending(x => x.Timestamp).ToListAsync());
}
