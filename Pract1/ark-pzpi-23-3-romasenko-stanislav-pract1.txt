2 ЗАВДАННЯ
Студент повинен обрати мову програмування, дослідити основні рекомендації для написання якісного коду у цій мові, продемонструвати ці рекомендації на прикладах коду, обґрунтувати кожну рекомендацію і надати детальні пояснення. Для кожного прикладу мають бути наведені фрагменти коду.
	Обрана мова програмування: C++
Ключові завдання: 
а) Дослідити та проаналізувати ключові стилістичні настанови для мови C++, зосередившись на Google C++ Style Guide та принципах Modern C++ (C++11/14/17).
б) Підготувати доповідь та презентацію з прикладами програмного коду, що демонструють необхідність та переваги застосування сучасних стандартів.
в) Продемонструвати рекомендації щодо:
•Форматування коду: Використання пробілів для відступів, обмеження довжини рядка (80/120 символів), правильна структура заголовних файлів (Header Guards / #pragma once).
•Іменування: Застосування різних стилів для візуального розрізнення сутностей: PascalCase для Типів (класів, структур) та snake_case для Змінних і Функцій.
•Сучасна Робота з Пам'яттю: Максимальне уникнення «сирих» вказівників (raw pointers) та операторів new/delete.
•Управління ресурсами (RAII): Демонстрація використання Smart Pointers (std::unique_ptr та std::shared_ptr) для запобігання витокам пам'яті (Memory Leaks).
•Безпека та Оптимізація (Const Correctness): Застосування правила const для змінних, методів класу та передачі важких об'єктів за константним посиланням (const reference).
•Архітектурні Підходи: Застосування принципів SOLID (зокрема SRP та DIP) для побудови гнучкої та підтримуваної архітектури системи.
•Тестування та Відлагодження: Огляд необхідності написання Unit Tests з використанням фреймворків (наприклад, Google Test) та навичок роботи з налагоджувачами (debugger).
3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Вступ до проблеми та завдання
У рамках практичної роботи було обрано мову програмування C++. Основне завдання полягало у дослідженні та демонстрації ключових настанов для написання якісного, безпечного та підтримуваного коду, зосередившись на офіційному стандарті Google C++ Style Guide та принципах Modern C++ (C++11/14/17).
3.2 Досліджені рекомендації та принципи
Для виконання завдання та підготовки доповіді було проаналізовано наступні ключові аспекти:
•Форматування коду (Відступи, Довжина рядка, Header Guards).
•Іменування (PascalCase, snake_case).
•Сучасна Робота з Пам'яттю (Smart Pointers, RAII).
•Const Correctness (Безпека та Оптимізація).
•Архітектурні Підходи (Принципи SOLID).
•Тестування та Відлагодження (Unit Tests, Debugger).
3.3 Опис виконаної роботи за слайдами
(Слайд 1: Титульна сторінка)
Представлено тему доповіді: «Основні рекомендації написання коду для мови C++». У вступі наголошено, що метою є демонстрація того, як писати чистий та безпечний код на основі стандартів Google Style Guide та Modern C++.
(Слайд 2: Вступ)
Обґрунтовано важливість дотримання стандартів. Зазначено, що потужність C++ та пряма робота з пам'яттю збільшують ризик критичних помилок (наприклад, Memory Leaks). Дотримання стандартів забезпечує: зменшення помилок, уніфікацію для всієї команди та прискорення процесу Code Review . Серед ключових стандартів названо Google C++ Style Guide, LLVM Coding Standards та C++ Core Guidelines.
(Слайд 3: Іменування)
Пояснено, що для візуального розрізнення сутностей використовується різна стилістика:
PascalCase (кожна літера з великої) – для Типів (Класів, Структур).
snake_case (маленькі літери через підкреслення) – для Змінних та Функцій.
Для Констант рекомендовано kPascalCase або ALL_CAPS.
(Слайд 4: Форматування)
Визначено ключові настанови щодо структури файлів та форматування:
Відступи: Використовуються пробіли (2 або 4) замість табуляції.
Довжина рядка: Рекомендовано обмеження до 80 або 120 символів для кращої читабельності при перегляді коду.
Заголовні файли (.h): Обов'язкове використання #pragma once або "Header Guards" для запобігання дублюванню підключень.
(Слайд 5: Робота з Пам'яттю)
Розкрито основний принцип Modern C++ – відмова від ручного керування пам'яттю за допомогою new та delete.
Показано діаграму класів Smart Pointer та пояснено використання Smart Pointers (розумних вказівників) для реалізації принципу RAII (Resource Acquisition Is Initialization).
std::unique_ptr: для сценаріїв, де ресурс має лише одного власника.
std::shared_ptr: для спільного володіння кількома об'єктами з автоматичним звільненням пам'яті через підрахунок посилань.
(Слайд 6: Const Correctness)
Наголошено, що const correctness – це "золоте правило C++" , яке підвищує безпеку та оптимізацію.
Принцип: "Якщо значення не змінюється — зроби його const".
Аргументи функцій: Рекомендовано передавати важкі об'єкти за константним посиланням (const reference) для уникнення зайвого копіювання даних та гарантування їх незмінності.
Методи класу: Позначаються як const, якщо вони не змінюють стан об'єкта.
(Слайд 7: Коментарі та Документація)
Визначено, що якісні коментарі та самодокументований код є ключовими для довгострокової підтримки.
Doxygen стиль (/** ... */ або ///) використовується для автоматичної генерації професійної документації .
Наголошено на необхідності використання осмислених назв для забезпечення самодокументованості коду.
(Слайд 8: Принципи SOLID)
Описано, що побудова архітектури має спиратися на перевірені Паттерни Проектування (Singleton, Factory, Observer) та Принципи SOLID. Приклади ключових принципів :
SRP (Єдина відповідальність): Кожен клас має відповідати лише за одну функціональність.
DIP (Інверсія залежностей): Модулі високого рівня повинні залежати від абстракцій, а не від модулів низького рівня.
(Слайд 9: Тестування та Відлагодження)
Підкреслено, що код вважається готовим лише після тестування.
Модульні тести (Unit Tests): Необхідно писати автоматизовані тести з використанням фреймворків, як-от Google Test або Catch2, для перевірки функціоналу та запобігання регресіям .
Ефективне відлагодження: Навичка роботи з налагоджувачами (debugger, наприклад GDB) є критично важливою для швидкого виявлення та виправлення помилок.
(Слайд 10: Висновки)
Підсумовано, що дотримання стандартів C++ (Google Style Guide, Smart Pointers, SOLID) є інвестицією в якість. Це робить код безпечним, читабельним та сучасним, що спрощує підтримку та зменшує кількість дефектів.


ВИСНОВКИ
У результаті виконання практичного завдання було: 
1.Досліджено основні стилістичні настанови для мови програмування C++, зокрема Google C++ Style Guide та принципи Modern C++ (C++11 і вище). 
2.Вивчено та обґрунтовано необхідність використання розумних вказівників (Smart Pointers), таких як std::unique_ptr та std::shared_ptr, для реалізації принципу RAII та запобігання витокам пам'яті. 
3.Проаналізовано конвенції іменування (PascalCase, snake_case) та правила форматування (відступи пробілами, обмеження довжини рядка), що забезпечують високу читабельність коду. 
4.Освоєно принцип Const Correctness як механізм підвищення безпеки та оптимізації коду шляхом гарантування незмінності даних. 
5.Розглянуто архітектурні підходи та важливість дотримання принципів SOLID для створення гнучкого та підтримуваного дизайну програмного забезпечення. 
6.Вивчено підходи до якісної документації коду через стандарти Doxygen та вимоги до самодокументованого коду. 
7.Ознайомлено з методологією модульного тестування (Unit Tests) із застосуванням фреймворків (наприклад, Google Test) та навичками ефективного відлагодження для забезпечення надійності функціоналу.
