3 ОПИС ВИКОНАНОЇ РОБОТИ
1. Текстовий опис інженерних рішень
1.1. Розгортання та конфігурація
Система розгорнута за допомогою Docker Compose, що дозволяє керувати багатоконтейнерною архітектурою як єдиним цілим.
1.API Server: Контейнеризований додаток на базі .NET 8, що використовує Dockerfile для збірки образу.
2.Database: Образ mcr.microsoft.com/mssql/server:2022-latest.
3.Мережа: Контейнери об'єднані у внутрішню віртуальну мережу Docker, що забезпечує безпечний зв'язок між API та БД без виставлення порту БД у зовнішній світ (окрім порту 1433 для розробки).
1.2. Вибір технологій
1.Docker: обраний для забезпечення ідентичності середовища розробки та виконання (Avoid "it works on my machine").
2.MS SQL Server: реляційна БД для забезпечення цілісності даних бронювань (ACID).
3.SignalR (WebSockets): протокол для миттєвого зв'язку між сервером та IoT-клієнтом (Push-сповіщення).
4.JWT (JSON Web Tokens): обрано для безпечної авторизації в розподіленій системі без збереження сесій на сервері (Stateless).

// Program.cs
using (var scope = app.Services.CreateScope())
{
    var services = scope.ServiceProvider;
    try
    {
        var context = services.GetRequiredService<RoomBookDbContext>();
        context.Database.EnsureCreated();
        DbInitializer.Seed(context); 
    }
    catch (Exception ex)
    {
        var logger = services.GetRequiredService<ILogger<Program>>();
        logger.LogError(ex, "Помилка при ініціалізації бази даних у Docker.");
    }
}

ВИСНОВОК
У ході виконання роботи було успішно реалізовано та розгорнуто розподілену систему RoomBook у середовищі Docker. Основні результати роботи включають:
Контейнеризація та оркестрація: За допомогою Docker Compose забезпечено стабільну взаємодію між сервером додатків (.NET API) та сервером бази даних (MS SQL Server), що гарантує ідентичність роботи системи на будь-якій платформі.
Автоматизація інфраструктури: Реалізовано механізм Data Seeding, який автоматично ініціалізує базу даних та створює активного адміністратора при першому запуску контейнерів. Це дозволило вирішити проблему "порожньої бази" в ізольованому середовищі.
IoT-інтеграція: Завдяки використанню протоколу SignalR налагоджено миттєву передачу сигналів від сервера до IoT-клієнта. Тестування підтвердило здатність системи керувати фізичними пристроями (електронними замками) у реальному часі.
Безпека та валідація: Система успішно виконує авторизацію за допомогою JWT-токенів та забезпечує цілісність бізнес-логіки через математичну перевірку конфліктів при бронюванні приміщень.
